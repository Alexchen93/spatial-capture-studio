# Spatial Capture

動態走拍與開源實作的技術對照，見 [動態拍攝與 3DGS 開源方案評估](./動態拍攝與3DGS_開源方案評估.md)。

目前網站為手機本機重建的實驗版本。首頁是介紹頁，`workspace.html` 預設只顯示一個「開始掃描」按鈕；進入滿版相機掃描後，可切換編輯模式使用原本分步驟的素材、重建與視察工作區。使用者可透過行動裝置錄影或選擇影片；影片由瀏覽器取樣成畫面，原始影片不會儲存到網站。擷取畫面與輔助照片僅保留在目前頁面的記憶體，可匯出 ZIP；重新整理會清除它們，不會從 IndexedDB 復原，且進入頁面時會清除舊版本留下的照片。已成功建立的個人場景另存於 IndexedDB，不隨刷新刪除。單支影片限制為 90 秒、500 MB，最多擷取 60 張畫面。網站透過 vendored MIT 授權的 Splat.js 在支援 WebGPU 的裝置上嘗試本機照片定位及 Gaussian Splatting 訓練，可匯出視覺 PLY；照片不經由該功能上傳。訓練會分別顯示已提交工作、WebGPU 佇列回應與訓練數值讀回；可在本機查看及複製診斷，資料不會自動上傳。低負載模式為未經 iPhone 實測的選用方案，不能保證成功；提前結束後需再按下載 PLY。實際手機相容性、訓練時間及結果品質尚未實機驗證，關閉頁面或 GPU 被回收可能中斷，輸出須由使用者下載保存。

右側示範場景仍是獨立的固定地面和手工牆面／家具碰撞，不是照片重建結果。訓練面板可切換已記錄的固定視角預覽。詳見 [手機本機重建技術補充](./手機本機重建_技術補充.md) 與工作區中的產品、系統架構及碰撞設計文件。

專案快速導覽頁位於 `/demo`（來源 `dist/demo.html`），以流程圖介紹記錄、擷取、實驗性重建、人工校正與視察，並提供實際操作入口。它不出現在首頁或工作區導覽，且標記 `noindex,nofollow`；但網址本身是公開的，不是密碼保護頁。

## 個人場景校正與步行（本機實驗）

工作區的「邊拍邊建立」會開啟相機，每約 1.8 秒選取一張亮度、細節及視角變化合格的畫面；滿 8 張就以低負載設定建立第一版粗模，拍攝仍可繼續。每新增 8 張後會用這次連續拍攝的全部畫面重新定位及重建，並覆寫同一個本機場景。這是**分批更新**，不是訓練引擎逐幀增量更新；新畫面要等下一輪才會進入模型，訓練和拍攝同時進行可能使手機發熱或運算中斷。最多連續擷取 60 張，照片刷新即清除；只有成功建立的模型會保存在目前瀏覽器。

滿版掃描將相機取景、3D 視角覆蓋殼及訓練中的 Gaussian 預覽排在同一畫面。模型區會明確顯示第一批 8 張有效照片的累積量、相機定位與訓練階段，訓練時顯示實際迭代進度；模型只會在成功定位、建立初始 splat 後逐步顯示，不會在按下掃描時立即憑空產生。下一批重新運算時，會嘗試保留上一輪模型的預覽畫面，直到新版開始更新。若裝置無法啟用 WebGPU，模型區會直接說明只能保存照片；若相機定位因重疊不足而失敗，會繼續拍攝，新增 8 張後重試；其他失敗會顯示原因並停止，照片僅保留到刷新，不會假裝模型已完成。

覆蓋殼的紅色表示尚未拍到的**方向**，黃色表示裝置方向感測器推估已拍到但尚未經 3D 定位確認，綠色表示已成功定位的重疊視角；可拖曳覆蓋殼查看其他方向。若瀏覽器未提供方向感測器，第一批畫面成功定位前會保持中性顏色。掃描完成建議須先有已儲存粗模，且至少 16 個已定位視角、12 個水平方向有重疊、地面與上方各至少 4 個方向；達標後才顯示「完成拍攝」。這是**可檢查模型的建議門檻**，不代表物件細節清晰、牆面無破洞或實際空間已完整量測；仍要由使用者檢查模型並視需要補拍。覆蓋殼不是已知牆面、家具或未重建幾何的精準空間標記；定位失敗的照片不會被當成綠色覆蓋。

從該流程進入第一人稱時，預設原點與起點使用第一張**成功定位**的拍攝畫面之相機位置，朝向使用該相機的水平朝向；地板高度及實際尺度仍是估計值，可進入編輯模式校正。若第一張無法定位，會使用最早成功定位的後續畫面；若起點不在有效步行範圍內，會移到最近可站立位置。相機與 WebGPU 同時運作及真實場景畫質尚未在目標手機實機驗證。

完成重建後，可在訓練面板選擇「儲存為個人步行場景」，再開啟個人場景頁；也可直接匯入本網站產生的 degree-0 Gaussian PLY（上限 128 MB、25 萬個 Gaussian）。PLY、相機姿態與校正資料只存於目前瀏覽器的 IndexedDB，不會同步到雲端，清除網站資料或更換瀏覽器可能使其遺失。已儲存場景開啟後會直接進入滿版第一人稱視察，畫面只保留「編輯模式」入口；首次匯入 PLY 或按下編輯模式時，可使用點雲俯視參考、相機位置、尺度／方向／地板調整、步行範圍，以及手動畫矩形碰撞區和數值編輯。按「儲存並進入視察」會儲存並返回視察；手機以單一拖曳控制移動。瀏覽器原生全螢幕僅能在使用者按鈕操作時啟用，直接開啟已儲存場景時仍會使用滿版網頁視察。步行時只對人工設定的矩形區與步行邊界做碰撞。

視覺 Gaussian PLY 不會自動推導可靠的牆面、地板、實際尺寸或家具碰撞；初始校正只是參考值，必須依現場測量人工檢查。步行預覽依賴 WebGPU；不支援 WebGPU 時仍可載入 PLY、編輯和儲存校正，但無法顯示第一人稱視角。此流程仍屬實驗，尚未以 iPhone Safari 實機或真實空間完成驗收，不能視為精準量測或安全保證；雲端帳號、API、資料庫、任務佇列與 GPU worker 尚未實作。

## 舊的本機桌面視覺重建實驗

`tools/reconstruct.py` 是先前的可選路線，編排本機已安裝的 Nerfstudio、COLMAP、FFmpeg 與 NVIDIA GPU，輸出 Gaussian Splat PLY。它未接入網站，且不產生碰撞模型。這不是手機或網站本機運算的必要依賴。

## 驗證

執行 `node --test tests/*.test.mjs` 檢查碰撞、照片 ZIP 和以模擬引擎驗證的重建狀態流程。影片擷取另以桌面瀏覽器和合成影片測試；尚未以 iPhone Safari 實測。模擬測試不能證明 GPU 重建可用；必須另在真實手機與真實照片上測試。網站靜態檔案位於 `dist/`。

## Cloudflare 部署

正式網站：https://spatial-capture.pages.dev/ 。Cloudflare Pages 專案名稱為 `spatial-capture`，採用 Direct Upload；網站來源是此專案的 `dist/`，GitHub 推送不會自動更新網站。

在已登入對應 Cloudflare 帳號（或已設定 `CLOUDFLARE_API_TOKEN`）的環境中，更新網站使用：

```bash
npx wrangler@latest pages deploy dist --project-name spatial-capture --branch main
```

部署後請確認首頁、`/workspace.html` 及其 JavaScript 模組可正常載入。實驗性 WebGPU 重建仍須在目標手機上實機驗證。
